## 结论

做完了：符号实验室；三支笔沙盘（墨笔写符、铅笔画路和图纸、朱笔划界）；第一代 10 个符的合成数据、小卷积网和混淆表；两张图纸（窝棚、发射台）的拟合。

机器测的结果（全是合成样本，还没有真人数据）：

| 指标 | 结果 | 过关线 |
|---|---|---|
| 第一猜就对（第一代各语境平均，常态） | **99.9%** | ≥ 97% |
| 第一猜就对（各语境平均，潦草：变形超出训练范围） | **96.7%** | ≥ 97% |
| 认错还生效 | **0.0%** | 约等于 0 |
| 乱画被拒（训练见过的 26 类，新种子） | **99.4%** | ≥ 95% |
| 乱画被拒（从没进过训练的 10 类） | **85.0%** | ≥ 95%，**没到** |
| 识别耗时 | Node 里每次 2–3 ms；浏览器里 4–8 ms | ≤ 10 ms |

- **没到线的是「没见过的乱画」。** 漏过去的大多本来就像某个符：伞像树，飞鸟像山，有的字母像旗。在游戏里，这些最多进「请选」，或者生效后 3 秒内撤回；收不回来的号令（雷火、烧荒、迁徙）本来就要再点一下确认。
- **潦草样本差 0.3 个点。** 潦草集故意比训练用的变形更大。十符全开时是 97.4%，过线。
- **真人样本还没有。** 过关线是按真人定的；真人数据作复核点，不卡下一步。复核的做法见第六节。

## 一、做了什么

| 部分 | 文件 | 说明 |
|---|---|---|
| 符与语境 | `src/recog/symbols.js` | 10 个象形符：日、月、雨、火、水、山、树、剑、旗、光。7 个语境（天、族人、树林、石堆、兽、河、空地），各有候选、动词、墨价，以及要不要确认 |
| 合成数据 | `src/recog/synth.js`、`negatives.js` | 每个符几种常见写法，再加手抖、断笔、多一笔、斜、扁、错切。乱画 26 类进训练，10 类（汉字笔画、字母、鱼、船、伞、鸟……）从不进训练 |
| 小卷积网 | `src/recog/cnn.js`、`tools/train.mjs` | 32×32 灰度输入，三层卷积（8/16/32），64 维特征，11 类（10 个符加「乱画」）。39,435 个参数，int8 存储，69 KB。用 14 个线程训练 4000 步，共 106 万条样本，约 6 分钟。手写推理，不引第三方库 |
| 识别器 | `src/recog/recognizer.js` | 三路合判：CNN、点云模板、和原型比特征。结论有四种：生效、请选、神意不明、这里用不上。个人原型来自示范三遍和每次生效的符，每个符留最近 30 个 |
| 门槛 | `tools/tune.mjs` | 用另一批种子调。约束是：常态 ≥ 99.7%、潦草 ≥ 97%、认错还生效 ≤ 0.05%；在此之下让乱画拒得最多 |
| 体检 | `tools/glyphcheck.mjs` → [`glyphcheck.md`](glyphcheck.md) | 逐语境的结果、混淆表、逐类的乱画、怪笔迹、耗时、真人样本 |
| 符圈 | `src/recog/group.js` | 停笔 0.45 秒（按你的节奏放宽，最多 0.9 秒）就收笔；在圈外点一下立刻收；在圈外起笔就是下一个符 |
| 朱笔 | `src/recog/redpen.js` | 用规则判，不用模型：长线是封锁线，圈起来是禁区，两笔交叉的 ✕ 是禁，一笔圈起来的 ○ 是护，一刀划过自己的线是启封 |

## 二、识别结果（合成样本）

详细表格见 [glyphcheck.md](glyphcheck.md)。下面是要点。

**各语境**（画在什么上面，就只比那几个符）：

| 语境 | 候选 | 常态 | 潦草 | 乱画被拒（见过 / 没见过） |
|---|---|---|---|---|
| 天 | 雨 日 月 火 | 100.0% | 98.9% | 99.6% / 92.8% |
| 族人 | 旗 光 月 火 剑 树 | 99.9% | 97.1% | 99.3% / 82.2% |
| 树林 | 剑 树 火 旗 | 99.8% | 96.3% | 99.4% / 82.9% |
| 石堆 | 剑 山 旗 | 99.8% | 95.7% | 99.4% / 86.8% |
| 兽 | 剑 火 旗 | 99.8% | 95.8% | 99.4% / 88.2% |
| 河 | 水 山 剑 旗 | 99.8% | 96.0% | 99.4% / 83.5% |
| 空地 | 树 旗 水 山 火 | 100.0% | 97.4% | 99.5% / 79.0% |
| **平均** | | **99.9%** | **96.7%** | **99.4% / 85.0%** |

- **两两混淆**：没有一对超过 1%。
- **单用一路**：只用 CNN，常态 100.0%、潦草 99.8%；只用点云，97.2% 和 88.6%。单用 CNN 时什么都给个答案，从不拒。合判后潦草样本有 2.5% 被误拒，换来的是乱画能被拒。
- **没见过的乱画，逐类（十符全开）**：
  - 伞 5%：当成树
  - 飞鸟 48%：当成山或水
  - 拉丁字母 62%：多半当成旗
  - 鱼 81%
  - 帆船 86%
  - 像字的笔画 87%
  - 杯子、钥匙、眼睛 100%
- **怪笔迹**：8 个「写字的人」，各有固定的斜、扁、错切，各写 20 遍。不示范时第一猜就对 94.6%（最差的一个是 63%）；每个符示范三遍后 99.8%。

## 三、三支笔和图纸

- **朱笔**：
  - ✕ 和 ○ 各 300 条手写变体，认对 ≥ 97%。
  - 29 类别的小涂画 ≥ 97% 不认。不算在内的是圆、方、三角、心形、多边形、十字、叉：这些本来就该算作 ○ 或 ✕。
  - ○ 的规则是「一笔圈起来，首尾接上，不太扁，不绕好几圈」，圆的、方的、三角的都算。
  - 封锁线的承受度按纸面长度算，线越长越薄。虎顶着线，承受度会往下掉，掉到 0 线就破。
- **图纸**：
  - 照淡影画，每一步都量得出来。
  - 手抖着画，20 次里至少 18 次能过。
  - 屋顶越陡，防雨越高。
  - 窝棚建成后的数值：容纳 4 人、防雨 64°、稳固 99%、保暖 95%、用料 木 10 · 草 8。
- **沙盘实测**：在浏览器里按真实时钟跑，用指针事件照真实的落笔节奏写，每条都核对了墨、天气、族人和日志：

  | 流程 | 结果 |
  |---|---|
  | 天上写雨 | 雨·降雨，扣 4 墨、下雨、食 +3 |
  | 点撤回 | 墨退回，个人原型里这条也删掉 |
  | 天上写火 | 先问「雷火收不回来，确定？」，确认后劈中一棵树 |
  | 空地上乱涂 | 神意不明，不扣墨 |
  | 朱笔封锁线 | 虎被挡住，承受度从 91 掉到 82；一刀启封 |
  | 树林上画 ✕，再写剑 | 禁伐生效，砍伐被拒，墨退回 |
  | 铅笔从营地拉长路 | 问要不要迁徙，确认后 8 个人沿路走过去，营地搬家 |
  | 图纸照淡影画四步 | 照图建成窝棚 |

  实验室里树、水、雨、光、剑这些多笔的符，快写也都认对，耗时 4–8 ms。版面在桌面、平板竖屏、手机竖屏和横屏下都看过。

## 四、这次查出来、已经修掉的问题

1. **符圈太紧，会把一个符切成两半。**
   - 毛病：先写树干、紧接着写树冠时，树冠的起笔落在树干的小圈外面，符就被切开了。
   - 量出来的：在实验室那么大写（约 280 像素），快写时 23.5% 的符被切开，水 76%、树 55%、雨 44%；沙盘里约 7%。
   - 改法：圈按已写笔画放大一倍。切开的降到约 1%。不修的话，真人样本会被这个毛病拖低。
2. **朱笔接断笔时会崩。** 三笔以上、要接起来的红符会让程序报错，已修好。量的时候还发现方块、三角算不算 ○ 时有时无，规则改成「一笔圈起来就算」。
3. **地图上的景物点太密。** 画符用的点距是按 1×1 的小框定的，放到 1600×1000 的地图上，一条河有 9.5 万个点，画出来是一道黑带，人和虎每帧都要重算几万笔。改成地图上另用 3 个单位的点距，河剩 384 个点。合成数据的默认值没动。
4. **朱笔的大小原来按纸面算。** 手机上地图缩到 1/4，一个小 ✕ 在纸面上就超过了封锁线的长度。改成按手底下画了多大算。
5. **小屏版面。** 顶栏原来挡住了天（写雨日月火的地方），参谋框压在树林上，手机上笔的按钮被提示盖住。都已调好。

## 五、和构想的出入

- **CNN 用 32×32，不是参考图里的 48×48。** 只用 CNN 时常态已经 100%，32×32 小一半、更快。两路投票改成了三路：多了「和原型比特征」，个人原型就是靠它起作用的。
- **第一代的符改成名词象形，动词看画在什么上面。** 同一个剑，画在树林上是砍伐、画在兽上是狩猎、画在石堆上是采石。10 个符能下 29 种号令；每次只比 3–6 个，所以稳。
- **迁徙不是符。** 用铅笔从营地画一条路线，再点确认。
- **数据只用合成的。** Quick, Draw! 没有下载，合成数据已经够过机器测。训练也用 JavaScript，不引 Python。
- **沙盘只为试输入。** 族人模拟、墨和信仰都是占位（墨每 2.5 秒回 1 点），M1 再做真的。

## 六、真人复核怎么做

1. 打开符号实验室，进「采样」。填写字的人，每个符写 10 遍，再乱画 20 条。
2. 进「数据」，点「导出 JSON」。
3. 运行：

   ```bash
   node tools/glyphcheck.mjs --human 文件.json
   ```

   几个人的文件可以一起评。
4. 看报告里的「四、真人样本」：各语境平均对过关线（第一猜就对 97%，乱画被拒 95%），再看最常见的错是哪几对。

这条路已经用一份合成的假样本走通过，假样本只用来验通路，不算结果。

## 七、下一步

- **识别上留着的事**：
  - 没见过的乱画只拒了 85%。如果真人数据也偏低，先补几类「半像符」的反例（伞、鸟、字母这类）再训一版，约 10 分钟。
  - 或者给最常误触的语境加确认。
  - 如果是某两个符老混，按构想的规矩改符号的设计，不去硬调模型。
